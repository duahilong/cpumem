# CPU/内存/硬盘 价格数据库设计文档

> 本文档总结价格数据库的设计思路、数据结构与查询方式。
> 数据来源：`价格图片/` 目录下的 64 张硬件报价单截图（CPU/内存/硬盘/外设实时报价）。

---

## 一、项目目标

把报价单图片中的价格信息提取出来，存入结构化数据库，支持以下核心查询：

1. **某型号 CPU 一段时间内的价格波动**（折线图展示）
2. **某型号某一天的价格**
3. **某型号硬盘/内存的价格波动**

核心两轴：**时间** 和 **价格**。库存、备注等属于次要信息。

---

## 二、整体流程

```
报价图片 → 多模态大模型提取(JSON) → 清洗规范化 → SQLite 入库 → 查询/画图
```

## 三、分类体系设计

三级分类树：**大类 → 品牌 → 型号**

```
大类 (category)      品牌 (vendor)            型号示例
─────────────       ─────────────           ─────────────
CPU                 Intel / AMD              i5-12400F / Ryzen 5 5600
内存                金士顿 / 三星 / 金百达...   FURY 16G 5600 / 银爵 16G 6000
固态硬盘            三星 / 西数 / 金士顿...     990 PRO 1TB / SN770 2TB
机械硬盘            西数 / 希捷               WD10EZEX / ST1000VX009
外设                罗技                      G502 / K845
```

**设计原则**：
- 大类和品牌是型号的**属性**，不单独建分类树表（集合小且稳定，单向归属）
- 分类信息存在型号维表 `products` 中，一个型号一行，不冗余到每条价格记录
- 大类 vocabulary 固定为：`CPU`、`内存`、`固态硬盘`、`机械硬盘`、`外设`
- 品牌 vocabulary 固定并归一（如 "Kingston" → "金士顿"）

## 四、数据结构（星型模型）

```
dates (日期维)          products (型号维: 分类+品牌)        quotes (价格事实)
┌──────────────┐      ┌──────────────────────────┐      ┌─────────────────────┐
│ 2026-09-16   │◄─────│ i5-12400f | CPU | Intel  │◄─────│ ..., 613, 散片      │
│ 2026-09-15   │      │ kingston-nv3-1tb |内存|金士顿│    │ ..., 720, 原盒      │
└──────────────┘      └──────────────────────────┘      └─────────────────────┘
```

### 4.1 维表1：products（型号表 —— 分类体系核心）

```sql
CREATE TABLE products (
    product_key   TEXT PRIMARY KEY,  -- 规范化键，如 'i5-12400f'、'kingston-nv3-1tb'
    display_name  TEXT NOT NULL,     -- 展示名，如 'Intel i5-12400F'
    category      TEXT NOT NULL,     -- 大类：CPU/内存/固态硬盘/机械硬盘/外设
    vendor        TEXT NOT NULL      -- 品牌：Intel/AMD/金士顿/三星...
);
```

- `product_key` 是规范化键（统一小写、去空格、统一连接符），解决同一型号写法漂移问题（`i5 12400F` / `I5-12400F` / `i5-12400F`）
- 修改品牌名/分类只需改此表一行

### 4.2 维表2：dates（日期表）

```sql
CREATE TABLE dates (
    date_key   TEXT PRIMARY KEY,     -- 'YYYY-MM-DD'
    year       INTEGER,
    month      INTEGER,
    day        INTEGER,
    weekday    INTEGER               -- 0=周一，便于看周期性规律
);
```

### 4.3 事实表：quotes（价格记录）

```sql
CREATE TABLE quotes (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    product_key   TEXT NOT NULL REFERENCES products(product_key),
    date_key      TEXT NOT NULL REFERENCES dates(date_key),
    price         REAL NOT NULL,       -- 数值价格（画波动图用）
    price_type    TEXT DEFAULT '默认',  -- 散片/原盒/单条/套装/默认
    price_raw     TEXT,                -- 原始文本，如 '17/17'、'690/705新'（溯源）
    source_image  TEXT                 -- 来源图片文件名
);
CREATE INDEX idx_q_prod_date  ON quotes(product_key, date_key);
CREATE INDEX idx_p_cat_vendor ON products(category, vendor);
```

### 4.4 关键设计决策

#### ① 一个价格 = 一行记录（长表，不是宽表）

报价单中一行有两个价格（如 `i5-12400F  17/17` = 散片价/原盒价），**拆成两条记录**：

```
product_key   date_key     price  price_type
i5-12400f     2026-09-16    613    散片
i5-12400f     2026-09-16    720    原盒
```

- ❌ 不用宽列（`sanpian_price, yuanhe_price`）：波动查询要写两遍 SQL，新增价格类型要改表
- ✅ 用 `price_type` 维度：任何型号任何价格类型都是同一条 SQL；内存的"单条价/套价"、硬盘的"含税/不含税"都是新的 type 值，无需改表

`price_type` 取值约定（清洗阶段做映射，保持稳定）：
- CPU：`散片` / `原盒`
- 内存：`单条` / `套装`
- 兜底：`默认`（只有一个价格时）

复合价格拆分示例：
- `17/17` → 散片 17 + 原盒 17
- `690/705新` → 散片 690 + 原盒 705
- `1800单条 3600套价` → 单条 1800 + 套装 3600

#### ② 日期必须从图片标题提取

文件名日期不可靠（`2026_09_16` 文件夹实际含 09-02~09-16 多期报价）。日期从图片内标题（"实时报价 2026-09-16"、"罗技产品报价 09月11日"）提取，无年份时用文件夹日期补齐，统一存 `YYYY-MM-DD`。

#### ③ 原文溯源

`price_raw` + `source_image` 保留原始信息，OCR 有误时可定位回原图人工修正。

## 五、提取方案：多模态大语言模型（非传统 OCR）

**结论：用支持图片输入的多模态大模型（Gemini / Qwen-VL 等），不用传统 OCR。**

| 维度 | 传统 OCR | 多模态 LLM |
|---|---|---|
| 多栏复杂版式 | 三栏并排不同品牌，列归属极易错 | 直接理解区块归属 |
| 列头-数据对应 | 需额外表格结构检测 | 要求"带列头输出"即可自动对齐 |
| 复合价格语义 | 只拿到字符串 | 直接输出 `{"散片": 17, "原盒": 17}` |
| 红字标注（新/少/订） | 彩色小字易漏 | 语义层面理解 |
| 输出 | 文本+坐标，需大量后处理 | 直接输出 JSON |

提取 prompt 要点：
1. 输出 JSON 数组：`category, vendor, product_name, price_type, price(纯数字), price_raw, date(从标题读)`
2. 严格按图片内容，不确定留空，不要推断
3. 一个型号两个价格 → 输出两条记录
4. 大类/品牌以表头区块标题为准传下来

质量兜底：抽查对比原图、一致性校验（同型号同日同类型重复、离谱价格值标记）。

## 六、查询示例

```sql
-- ① 某CPU一段时间价格波动
SELECT d.date_key, q.price, q.price_type
FROM quotes q
JOIN products p ON q.product_key = p.product_key
JOIN dates d    ON q.date_key = d.date_key
WHERE p.display_name LIKE '%i5-12400F%'
  AND p.vendor='Intel' AND p.category='CPU'
  AND q.price_type='散片'
  AND d.date_key BETWEEN '2026-09-01' AND '2026-09-16'
ORDER BY d.date_key;

-- ② 某天某CPU的价格（去掉 BETWEEN，加 d.date_key = '2026-09-16'）

-- ③ 浏览：某品牌/大类下的型号（下拉框）
SELECT vendor, display_name FROM products WHERE category='CPU' ORDER BY vendor;

-- ④ 某品牌全部产品最新一期报价
SELECT p.display_name, q.price_type, q.price
FROM quotes q JOIN products p ON q.product_key=p.product_key
WHERE p.vendor='金士顿'
  AND q.date_key = (SELECT MAX(date_key) FROM quotes);
```

折线图 = 时间序列查询结果 + matplotlib（见 `plot_demo.py`），支持单线走势、双线对比（散片 vs 原盒）。
