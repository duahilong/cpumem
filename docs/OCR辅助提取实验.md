# OCR 辅助提取实验与方案文档

本文档记录 **OCR 辅助提取方案**的完整实验演化过程：动机、各阶段实验、关键结论，以及最终定稿并入主管线的方式。它是 [`CPU提取管线.md`](CPU提取管线.md) 的配套文档——那份描述当前定稿的管线实现，本文档记录"如何走到这一步"的实验轨迹与经验教训。

> 说明：实验基于本地部署的 GLM-OCR 模型（2026-09 进行）。所有准确率数据以 `verify.py` 对比人工基准为准。

---

## 1. 实验动机

纯视觉管线（裁剪图直接交多模态 LLM）存在两类主要失败模式：

1. **行串位/整列 shift**：LLM 从像素定位行列时把相邻行的价格串到一起（如 12700F 拿到 12700KF 的价）；
2. **原盒价漏提**：U 系/15-16 代区域的原盒列经常被漏读。

核心思路：报价单上的**数字识别是确定性任务**，专用 OCR 模型在数字识别上接近 100% 准确。把 OCR 输出作为结构化证据交给 LLM，理论上可以抑制读数幻觉、稳定行列对齐。实验验证了这个思路，最终演化为"**OCR 为主、图为辅**"的两步式提取结构。

---

## 2. 实验演化轨迹（五个阶段）

### 阶段 1：OCR 部署与数字识别验证（Ollama GLM-OCR）

- 部署：Ollama（`localhost:11434`）`glm-ocr:latest`；
- **关键坑**：Ollama 默认 `num_ctx` 太小，OCR 输出在 ~440 tokens 截断（`done_reason=length`），只读到表格前 1/4。必须显式传 `options: {num_ctx: 16384, num_predict: 16384}`；
- **结论**：数字识别零错误（0a04 基准 64/64 价格点），"新/少/拆/在途/下午"标注和 `****` 异常标记完整保留——OCR 数字通道可信。

### 阶段 2：OCR Prompt 选型

测过 4 种风格：

| 风格 | 结论 |
|---|---|
| HTML 表格转写 | 模型实际输出格式（`<table>/<td>`，含 rowspan/colspan），行列结构最清晰 |
| 纯文本转写 | 数字同样零错误，但行列靠制表符，有跨区粘连 |
| 逐行 JSON 对象 | **完全失败**：只输出第一行就停，GLM-OCR 不支持复杂指令 |
| Markdown 管道表格 | 实际也输出 HTML——**模型输出格式固定为 HTML，prompt 无法改变** |

关键发现：**prompt 措辞对输出几乎无影响**（"识别图片中的所有文字，输出为Markdown格式"与详细 HTML 转写 prompt 输出完全一致），最终 prompt 定为简短版："识别图片中的所有文字，输出为Markdown格式"，下游按 HTML 解析。

同时发现 **Ollama 版输出有随机性**：同 prompt 多轮覆盖率在 76.6%~96.9% 之间波动，随机漏"红色高亮带'新'的特价"和三型号行价格——这是模型温度随机性，prompt 只能缓解。

### 阶段 3：联合提示词（图为先 + OCR 参考）

结构：base.txt + CPU.txt + 白名单 + 联合规则（6 条）+ OCR Markdown。在 0a04 上 6 轮调优：

- **关键修复**：base.txt 的"含星号价格视为无效"规则会拦截 `480/****`（G6900 案例，实际是有效价格）。联合规则第 5 条明确"数字+**** 有效、纯 **** 才无价"后修复；
- 0a04 达到 99.2%~100%。

### 阶段 4：换 llama.cpp 部署（确定性输出）

换 llama.cpp 部署 GLM-OCR（GGUF Q8_0，`127.0.0.1:8080`）后的重大发现：

- **同 prompt + temperature=0 跑 3 遍输出字节级完全一致**——彻底消除 Ollama 版的随机漏单元格问题，OCR 缓存变得安全可复用；
- OpenAI 兼容接口与现有 `call_llm()` 格式一致，接入成本低。

### 阶段 5：提示词结构反转（OCR 为主、图为辅）→ 定稿

在 0b5a（2026-09-11 期，87 型号基准，纯视觉 92.7%）上测试了四种提示词结构：

| 结构 | 0b5a 准确率 | 提示词长度 | LLM 耗时 |
|---|---|---|---|
| 旧结构：图为先 + OCR 参考 | 95.9% | ~8800 字符 | 88s |
| **新结构：OCR 为主 + 图为辅（两步式）** | **95.3%** | **5382 字符** | **41s** |
| 纯 OCR（无图） | 94.5% | ~6000 | 47s |
| 纯视觉（无 OCR） | 92.7% | ~5100 | ~50s |

新结构的核心设计：
- **第一步**：从 OCR 表格提取（主要来源，8 条规则含 JSON 契约）；
- **第二步**：用原图核对 OCR 不确定项（消歧：同名多行回图确认 F/KF/K、前缀可疑、粘连单元格）；
- 完全抛弃 base.txt/CPU.txt（消除 `****` 规则冲突），JSON 契约内联且字段说明完整。

准确率与旧结构打平（差 0.6pp，1 个核对点，在波动范围内），但 token 省 40%、耗时快一半、结构更干净，**定稿采用新结构**并合入主管线（见第 4 节）。

## 3. 关键实验结论（经验教训）

1. **OCR 数字通道可信**：GLM-OCR 在报价单数字上零错误（两期基准均验证），可以作为高置信度证据；
2. **OCR 的弱点是型号名细节和排版**：偶发 F/KF/K 后缀误识（`12700KF`→`12700F`）、前缀误识（`I9 13900F`→`I7`）、相邻行同名粘连、colspan 区块头（`AMD散片 830`）——这些需要原图通道消歧；
3. **纯 OCR（无图）可行但漏提更多**（0b5a：94.5% vs 联合 95.3%~95.9%）——12700 系列三行同名时无图对照整组判不了列归属；纯 OCR 可作为降级思路但未合入管线；
4. **纯视觉降级无意义**：提示词以 OCR 为主后，无 OCR 时旧提示词体系与当前 JSON 契约不一致，静默降级会导致质量不可预期——OCR 失败应明确报错计入失败清单；
5. **确定性输出是工程基石**：llama.cpp + temperature=0 让 OCR 缓存安全、结果可复现；
6. **模型输出格式不可强改**：GLM-OCR 固定输出 HTML 表格，下游做格式统一（HTML→Markdown 转换）比强行改 prompt 可靠。

## 4. 定稿并入主管线的方式

最终方案已合入 `database/extract_cpu.py`（详见 [`CPU提取管线.md`](CPU提取管线.md)）：

- **OCR 通道**：`ocr_markdown()` 调 llama.cpp GLM-OCR（地址在 `llm_config.json` 的 `ocr_base_url` 配置，当前 `http://127.0.0.1:8080`；prompt 简短版，temperature=0），HTML → `html_table_to_markdown()` 转 Markdown，缓存 `ocr_cache/`；失败抛 `RuntimeError`（该图计失败，不降级）；
- **提示词**：`prompts/OCR主_指令.txt`（新结构指令，含 JSON 契约/白名单/消歧规则）+ OCR Markdown 数据区；base.txt/CPU.txt 不再使用（`build_cpu_prompt()` 保留但无调用方）；
- **纯顺序单路径**：S1 断点检查 → S2 锚点裁剪 → S3 OCR → S4 提示词 → S5 LLM → S6 落盘；无降级分支。

定稿验证（两期人工基准）：

| 图片 | 图期 | 基准 | 准确率 |
|---|---|---|---|
| `0a04d486…png` | 2026-03-11 | `jg.xlsx`（78 型号） | **100%**（132/132） |
| `0b5aad69…png` | 2026-09-11 | `0b5a-pricebenchmark.xlsx`（87 型号） | **95.3%**（141/148） |

0b5a 残余 7 项错误的根因：OCR 型号名误识（12700 系列三行同名、13900F 前缀）+ 疑似基准口径差异（13100/13100F、9850X3D，待人工核图）。

## 5. 实验过程中的经验备忘

1. **Ollama `num_ctx` 截断**：部署 OCR 类模型必须显式加大上下文，否则输出静默截断（`done_reason=length`）；
2. **GLM-OCR 不支持复杂指令**：让它做语义拆分/JSON 输出会提前停止，只用它做表格转写；
3. **OCR 随机性 vs 确定性**：Ollama 版有温度随机性（多轮漏单元格不同），llama.cpp + temperature=0 完全确定——选部署方式时确定性是关键考量；
4. **提示词规则冲突**：多套提示词叠加时（base.txt + 联合规则）必须检查语义矛盾（`****` 案例），矛盾规则会让 LLM 行为不稳定；
5. **结构化数据反转信息流**：有了高置信度的结构化中间层（OCR Markdown）后，把"主要信息来源"从图反转为文本、图降为消歧，能同时省 token、降耗时、简化指令；
6. **缓存分层**：裁剪（`crop_cache/`）、OCR（`ocr_cache/`）、结果（`extracted_cpu/`）三层缓存按文件名复用，改哪层逻辑清哪层缓存。

## 6. 遗留与可选方向

1. **0b5a 残余错误的口径确认**：13100/13100F、9850X3D 几项疑似基准与图面的口径差异，待人工核图后更新基准；
2. **纯 OCR 降级模式**：实验证明可行（94.5%），若未来需要"OCR 服务挂了但缓存存在"的容错场景，可作为降级分支合入（当前未合入，管线保持纯顺序）；
